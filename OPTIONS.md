# Идеи и их варианты: топ-3 на каждую

Зачем этот файл: любая идея не должна держаться на одном репозитории. Здесь у каждой идеи —
**формулировка** (чтобы её можно было реализовать и без этих репозиториев) и **три варианта
из уже отмеченных звёзд**: основной + альтернатива + дополнение.

У каждой идеи два слоя: **топ-3 из моих звёзд** и отдельный блок **«вне звёзд»** — что нашлось
поиском на стороне, с проверенными через GitHub API звёздами и лицензиями. Кандидаты, которые
стоит отметить, собраны в конце файла.

Правило чтения: если репозиторий завтра исчезнет, идея остаётся. Репозитории — доноры решений,
а не фундамент.

## A. Центр агентов

### A1. «Очередь задач вместо чата»

**Формулировка.** Работа агенту выдаётся карточкой в очереди, а не сообщением в чате. Карточка
имеет статус, исполнителя, критерий готовности и результат. Человек разбирает результаты пачкой,
а не сидит в диалоге.

**Топ-3:**
1. **`BloopAI/vibe-kanban`** — основной. Готовая модель «доска → параллельные агенты → разбор».
2. **`code-yeongyu/oh-my-openagent`** — альтернатива. Вместо доски — явный граф работ: задача
   раскладывается в DAG, узлы исполняются отдельно.
3. **`razzant/claudexor`** — дополнение. Диспетчер над несколькими харнессами: кому отдать
   карточку с учётом квот.

**Что выбрать.** Для центра агентов — vibe-kanban как UX-образец; граф из oh-my-openagent
брать, если появятся задачи с зависимостями (сборка → тесты → ревью).

**Вне звёзд (найдено поиском):**
- `andyrewlee/awesome-agent-orchestrators` ★2.2k — реестр открытых оркестраторов агентов (CC0):
  сначала смотреть там, потом строить своё.
- `makeplane/plane` ★61k (AGPL-3.0) — если очередь нужна команде, а не только агентам:
  полноценный трекер с открытым кодом.

### A2. «Один шлюз к моделям»

**Формулировка.** Все агенты ходят в модели через один внутренний интерфейс. Смена провайдера —
правка конфига, а не кода. Лимиты и стоимость видны в одном месте.

**Топ-3:**
1. **`lidge-jun/opencodex`** — основной. Готовый прокси: один формат API поверх Claude, Gemini,
   Grok, DeepSeek.
2. **`signerless/llm-checker`** — альтернатива/дополнение. Сканирует железо и говорит, какие
   локальные модели реально потянет — половина трафика уходит на локальный инференс.
3. **`mnfst/awesome-free-llm-apis`** + **`vava-nessa/free-coding-models`** — дополнение.
   Каталог бесплатных API и кодовых моделей: чем закрыть прототипы без бюджета.

**Что выбрать.** Начать с opencodex; llm-checker прогнать один раз, чтобы понять потолок локалки.

**Вне звёзд (найдено поиском):**
- `BerriAI/litellm` ★62k — промышленный шлюз к 100+ LLM API в формате OpenAI; прямая замена
  самодельного прокси. Лицензия нестандартная — проверить перед коммерческим использованием.
- `simonw/llm` ★13k (Apache-2.0) — CLI-доступ к моделям и шаблоны промптов: удобно для скриптов
  и отладки.

### A3. «Навык как переносимая единица»

**Формулировка.** Повторяемое умение агента живёт отдельным файлом с описанием, входом и
критерием результата. Навык можно версионировать, включать по проекту и переносить между
агентами без переписывания.

**Топ-3:**
1. **`danielmiessler/Fabric`** — основной. 266 паттернов, формат «папка = паттерн = `system.md`» —
   самая проверенная структура библиотеки.
2. **`Jeffallan/claude-skills`** — альтернатива. 67 навыков в формате `SKILL.md` + assets:
   как оформлять входные материалы и скрипты.
3. **`larashero3-dotcom/lieflat-charts`** — дополнение. Навык, который отдаёт готовый артефакт
   (HTML-график), а не зависит от библиотеки в проекте.

**Что выбрать.** Формат — от Fabric (плоско, без магии), метаданные и assets — от Jeffallan.
`alirezarezvani/claude-skills` (380 навыков) держать как источник идей, не как образец структуры.

**Вне звёзд (найдено поиском):**
- `simonw/llm` ★13k (Apache-2.0) — шаблоны промптов и история в SQLite: минималистичная
  альтернатива библиотеке паттернов.
- `modelcontextprotocol/servers` ★91k — официальные MCP-серверы: готовые инструменты вместо
  написания навыков с нуля.

### A4. «Человек подтверждает, а не наблюдает»

**Формулировка.** Агент показывает, что он собирается сделать, и ждёт решения там, где человек
уже находится. Подтверждение — одно действие, а не переключение в терминал.

**Топ-3:**
1. **`asafofer/perch`** — основной. Allow/Deny прямо из нотча + возврат в нужную сессию.
2. **`jgouviergmail/LIA-Assistant`** — альтернатива. Human-in-the-Loop как узел графа: где именно
   ставится пауза и как возвращается ответ.
3. **`ANDRETRIPOL/OpenGhost`** — дополнение. Разрешения на уровне ОС: что агент может трогать
   без спроса, а что только с подтверждением.

**Что выбрать.** UX — у perch; архитектуру паузы/возврата — у LIA; модель разрешений — у OpenGhost.

**Вне звёзд (найдено поиском):**
- `humanlayer/humanlayer` ★12k — HITL-платформа: перехват вызова инструмента до исполнения
  и подтверждение через интерфейс. Лицензия нестандартная — проверить.
- `MioMioOS/MioIsland` ★538 (Swift) — approve и переход в сессию прямо из Dynamic Island.

## B. Нативные приложения macOS

### B1. «Приложение из готовых нативных доноров»

**Формулировка.** Новое приложение собирается не с нуля, а из проверенных открытых компонентов:
браузерное ядро, поиск, чат. Свой код — только продуктовая оболочка.

**Топ-3:**
1. **`driceroland/Search`** — основной. Маленький быстрый WebKit-браузер: база для
   `dajet-browser`.
2. **`ARahim3/DigUp`** — альтернатива. On-device поиск по содержимому файлов: если продукту
   нужен поиск, а не только просмотр.
3. **`jaywcjlove/awesome-swift-macos-apps`** — дополнение. Каталог доноров по категориям
   (Audio, Browser, Editors, Local LLM) — сначала искать там, потом писать.

**Что выбрать.** Для браузера — Search; для «умного поиска» — DigUp; список — как карту рынка,
а не как код.

**Вне звёзд (найдено поиском):**
- `alienator88/Pearcleaner` ★15k (Swift) — чистильщик приложений с открытым кодом: живой пример
  Swift-утилиты с системными правами. Лицензия fair-code, не OSI.
- `tddworks/ClaudeBar` ★1.6k (Swift, Apache-2.0) — маленькое menu bar-приложение: читаемый проект
  для старта.

### B2. «Menu bar — основной интерфейс»

**Формулировка.** Постоянное приложение не открывает окно. Оно живёт в menu bar или нотче и
появляется только тогда, когда есть что сказать или спросить.

**Топ-3:**
1. **`asafofer/perch`** — основной. Нотч, статусы, карточки, тишина по умолчанию.
2. **`bestdeejay-design/sweet-no-sleep`** — альтернатива. Своя маленькая menu-bar утилита:
   минимальный каркас, который уже работает.
3. **`clash-verge-rev/clash-verge-rev`** — дополнение. Панель + трей + профили на Tauri:
   если понадобится кроссплатформенность.

**Что выбрать.** Каркас — из sweet-no-sleep, поведение и тишину — из perch.

**Вне звёзд (найдено поиском):**
- `MioMioOS/MioIsland` ★538 (Swift) — Dynamic Island для агентов: мониторинг, approve, переход
  в сессию.
- `tddworks/ClaudeBar` ★1.6k (Swift, Apache-2.0) — второй взгляд на menu bar: квоты и расход
  вместо сессий.

### B3. «Маленький клиент вместо тяжёлого»

**Формулировка.** Приложение решает одну задачу, весит десятки мегабайт и запускается мгновенно.
Никакого Electron и облачных зависимостей.

**Топ-3:**
1. **`t8y2/dbx`** — основной. 25 МБ на 100+ баз данных: пример дисциплины размера.
2. **`tw93/Mole`** — альтернатива. CLI + TUI, который ощущается как продукт, плюс нативное
   приложение отдельно.
3. **`driceroland/Search`** — дополнение. Минимум кода для полноценного окна с WebKit.

**Что выбрать.** Как планку «сколько это должно весить» — dbx; как планку «как выглядит
терминальный продукт» — Mole.

**Вне звёзд (найдено поиском):**
- `alienator88/Pearcleaner` ★15k — небольшая нативная утилита, решающая одну задачу.
- `tddworks/ClaudeBar` ★1.6k — минимальный Swift-проект под MenuBarExtra.

## C. LOVII CRM

### C1. «Доказательство вместо уверенности»

**Формулировка.** Агент не пишет в карточку «вероятно, это та же компания». Каждый факт
сопровождается источником и силой доказательства; слабое — уходит человеку как предложение,
а не в запись.

**Топ-3:**
1. **`trycompai/crm`** — основной. Инструменты возвращают наблюдения, леджер оценивает,
   запись или предложение — разные пути. Плюс `skills/evidence.md` как регламент.
2. **`mazze93/stratum`** — альтернатива. Append-only леджер решений: история не переписывается,
   видно, на чём основывались.
3. **`arthurpanhku/DocSentinel`** — дополнение. Оценка документа с обоснованием через MCP:
   проверять карточку по первичке, а не по пересказу.

**Что выбрать.** Механику — из crm; формат хранения истории — из stratum; проверку документов —
из DocSentinel.

**Вне звёзд (найдено поиском):**
- Прямого аналога «леджера доказательств» не нашлось: только подходы в блогах. Ниша свободна —
  и это аргумент делать своё.
- `twentyhq/twenty` ★59k — открытая CRM «под AI» (замена Salesforce). Не леджер, а готовая база,
  если понадобится фундамент вместо своего.

### C2. «У агента есть роль и права»

**Формулировка.** Агент — участник с ограниченными полномочиями: что читает, что меняет, что
только предлагает. Права задаются ролью, а не доверием к промпту.

**Топ-3:**
1. **`croffasia/itsaplan`** — основной. Роль, права и слот исполнителя у агента наравне с людьми.
   **Лицензия AGPL-3.0: только изучение, код не втаскивать.**
2. **`trycompai/crm`** — альтернатива. `skills/data-boundaries.md` и разделение «API сообщает
   факт / агент решает смысл» — граница полномочий на уровне кода.
3. **`ANDRETRIPOL/OpenGhost`** — дополнение. Разрешения ОС: файлы, приложения, сеть.

**Что выбрать.** Модель ролей — из itsaplan; инженерную реализацию границ — из crm.

**Вне звёзд (найдено поиском):**
- `makeplane/plane` ★61k (AGPL-3.0) — трекер с ролями и правами; альтернатива itsaplan
  с той же лицензионной оговоркой.
- `hcengineering/platform` (Huly) ★28k (EPL-2.0) — all-in-one PM; EPL мягче AGPL, но копилефт.

### C3. «Артефакт из данных: КП, отчёт, презентация»

**Формулировка.** Из данных карточки или базы собирается готовый документ под клиента —
без дизайнера и без ручной вёрстки. Данные → структура → артефакт.

**Топ-3:**
1. **`presenton/presenton`** — основной. Документ → слайды, self-hosted, есть API.
2. **`thesysdev/openui`** — альтернатива. Если нужен не файл, а живой интерактивный отчёт:
   компактный язык разметки, который модель стримит.
3. **`larashero3-dotcom/lieflat-charts`** — дополнение. Графики как самостоятельный HTML —
   вставлять в отчёт без зависимостей.

**Что выбрать.** Презентации — presenton; дашборд/отчёт в браузере — openui; графики — lieflat.

**Вне звёзд (найдено поиском):**
- `slidevjs/slidev` ★49k (MIT) — слайды как markdown-код: детерминированная альтернатива
  AI-генерации, когда важна точность, а не скорость.
- `vercel-labs/json-render` ★19k (Apache-2.0) — generative UI от Vercel: интерфейс ограничен
  компонентами, которые ты определил.
- `tambo-ai/tambo` ★11k (MIT) и `CopilotKit/CopilotKit` ★38k (MIT) — SDK для generative UI в React.

### C4. «Тесты интеграций без провайдера»

**Формулировка.** Платёжные и фискальные сценарии проверяются на моках, повторяющих поведение
реального провайдера, включая ошибки и таймауты. Никаких боевых ключей в тестах.

**Топ-3:**
1. **`rucorp/mock-services`** — основной. Моки эквайринга и ОФД под тесты.
2. **`caddyserver/caddy`** — дополнение. Локальный HTTPS-вход, чтобы вебхуки ходили по тем же
   адресам, что в проде.
3. **`oauth2-proxy/oauth2-proxy`** — дополнение. Проверить сценарии доступа до того, как
   появится настоящий IdP.

**Что выбрать.** mock-services — обязательно; остальное — по мере роста интеграций.

**Вне звёзд (найдено поиском):**
- Открытых моков эквайринга/ОФД под российских провайдеров не нашлось. `mock-services` остаётся
  основным вариантом — и это ещё одна причина держать его в звёздах.
