# Регламент сессий opencode — как не потеряться между проектами

> Единый источник правды: **repo-catalog** (этот репозиторий).
> В каждом чате opencode — только один проект + ссылки на планы отсюда.
> Общие описания, регламенты и планы живут здесь, а не в чатах.

---

## Принцип

- **Один чат = один проект.** Не смешиваем проекты в одном чате — теряется контекст.
- **Этот чат / этот репозиторий = штаб.** Здесь: каталог репозиториев, дорожные карты, регламенты, решения.
- Перед началом работы над проектом — открыть **новую сессию** и назвать её по проекту.

## Протокол открытия сессии по проекту

1. Открыть новый чат в opencode (не продолжать этот).
2. Название чата — по проекту, например: `alfred-product`, `aichat-local`.
3. Первым сообщением в новом чате дать агенту контекст:
   - «Проект: alfred. План: DEMO_ROADMAP.md → секция alfred (см. repo-catalog). Репо: bestdeejay-design/alfred. Локально: ~/Projects/...»
   - (при необходимости — склонировать репозиторий локально)
4. Работать строго в рамках одной задачи из плана. Готово → отметить в плане → отчитаться в штаб-чат.
5. Не плодить файлы планов в чатах: все решения фиксировать здесь (PR в repo-catalog).

---

## Протокол возвращения в проект

Если сессия потерялась/закрылась:
1. Открыть `repo-catalog` → `DEMO_ROADMAP.md` / `SESSIONS.md`.
2. Прочитать статус проекта (колонка «Статус»).
3. Открыть новую сессию по правилам выше и продолжить с места остановки.

---

## Правила для агента (Sisyphus)

- Работая в сессии проекта — не менять `repo-catalog` без явной просьбы (это штаб).
- Завершив этап — обновлять статус в `DEMO_ROADMAP.md` и `SESSIONS.md` (через штаб-чат или PR).
- Не создавать новые репозитории без согласования; имена и описания — через каталог.
- Решения по стратегии (лицензии, платформы, брендинг) фиксировать в `DEMO_ROADMAP.md` — чаты недолговечны.
