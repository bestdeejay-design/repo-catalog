# Отчёты по дням

Здесь лежит ежедневный срез по **всем** репозиториям и **всем** доскам GitHub Projects.

## Куда что пишется

```
reports/
├── index.md                 # оглавление: все дни одной таблицей
├── latest.md → 2026/…       # симлинк на свежий отчёт
├── 2026/
│   ├── 2026-11-03.md        # отчёт за день, читать человеку
│   └── 2026-11-03.json      # машинный снимок: те же данные + коммиты поштучно
└── README.md                # этот файл
```

Правила:

- **Один день — одна пара файлов.** `.md` для чтения, `.json` для диффов и скриптов.
- **Ничего не удаляем.** Отчёты копятся, это история. Год = одна папка.
- Каталог под git (`repo-catalog`), поэтому каждый отчёт автоматически уезжает
  на GitHub — отдельного бэкапа не требуется.
- Отчёт за день не переписывается задним числом, кроме повторного запуска за тот же день.

## Как собрать

```bash
cd ~/Projects
export PATH="/opt/homebrew/bin:$PATH"      # gh живёт здесь

python3 repo-catalog/daily_report.py                    # сегодня, полный обход
python3 repo-catalog/daily_report.py --local            # + локальные долги ~/Projects
python3 repo-catalog/daily_report.py --date 2026-11-02  # конкретный день
python3 repo-catalog/daily_report.py --no-repos         # только доски, ~20 с
```

Требуется только `gh` с правами `project` + `repo` (уже авторизован как `bestdeejay-design`).
Python — стандартная библиотека, ставить нечего.

Время полного прогона: **~60 с** (146 репозиториев, 6 досок).

## Что внутри отчёта

| Раздел | Что отвечает на вопрос |
|---|---|
| 1. Сводка | сколько добавлено / выполнено / в работе, сколько коммитов |
| 2. Доски | состояние каждой доски на конец дня: всего / не начато / в работе / готово |
| 3. Добавленные сегодня | карточки, попавшие на доску за день, с датой создания задачи |
| 4. Выполненные сегодня | issue и PR, закрытые (или влитые) за день |
| 5. В процессе | задачи в статусе «в работе» и сколько дней нет движения |
| 6. Активность репозиториев | коммиты, новые и закрытые issue, PR по каждому репозиторию |
| 6a. Новые issue вне досок | задачи завели, а на доску не поставили |
| 7. Требует внимания | зависшее «в работе», «готово» при открытом issue, пустые доски |
| 8. Локальные долги | что не запушено и что грязно в `~/Projects` (только с `--local`) |

## Как считается день

Календарный день по Москве, `00:00–24:00 MSK`. Даты берутся из GitHub:

- «добавленные» — `createdAt` карточки **в проекте** (когда попала на доску), а не дата issue;
- «выполненные» — `closedAt` / `mergedAt` issue или PR;
- «в процессе» — текущий статус карточки `In Progress` / `В работе` / `На проверке`;
- коммиты — ветка по умолчанию, не больше 100 на репозиторий.

Статусы досок бывают на английском и русском (`Done`/`Готово`, `In Progress`/`В работе`),
словари — в начале `daily_report.py`. Новый статус добавляется одной строкой в
`DONE_WORDS` или `WIP_WORDS`.

**Ограничение ретроспективы.** Отчёт за прошлый день честно покажет, что закрыли и
что добавили в тот день, но раздел «Доски» будет отражать **текущее** состояние —
GitHub не отдаёт историю статусов карточки. Для ежедневного использования это неважно:
отчёт пишется в тот же день.

## Расписание

### Вариант A — launchd на ноутбуке (рекомендуется)

`ops/run-daily.sh` собирает отчёт с локальными долгами и коммитит результат в `repo-catalog`.

```bash
cp repo-catalog/ops/com.local.daily-report.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.local.daily-report.plist
# проверить: launchctl list | grep daily-report
# выключить: launchctl unload ~/Library/LaunchAgents/com.local.daily-report.plist
```

Запуск ежедневно в 09:30 MSK. Лог — `~/.local/share/daily-report/run.log`.
Если ноутбук спал в 09:30, launchd выполнит задачу при пробуждении.

### Вариант B — GitHub Actions

Плюс: работает без ноутбука. Минус: нет раздела «Локальные долги», и нужен
personal access token со scope `project` в секретах — токен Actions к проектам
user-аккаунта доступа не имеет.

### Вариант C — вручную

Команда из раздела «Как собрать». Ничего не настраивается.

## Если что-то сломалось

| Симптом | Причина | Что делать |
|---|---|---|
| `gh: command not found` | нет `/opt/homebrew/bin` в PATH | `export PATH="/opt/homebrew/bin:$PATH"` |
| Пустые доски | истёк scope `project` | `gh auth refresh -s project` |
| `403` в активности | упёрлись в лимит API | подождать до `reset`, проверить `gh api rate_limit` |
| Доска «пуста» в разделе 7 | проектов без карточек | либо наполнить, либо закрыть доску |
| В отчёте нет нового репозитория | он в аккаунте вне списка `OWNERS` | добавить владельца в `OWNERS` в `daily_report.py` |
