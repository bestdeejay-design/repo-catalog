# Разбор восьмёрки — что в этих репозиториях на самом деле

Разбор сделан по README и структуре репозиториев (GitHub API: дерево, наличие файлов, счётчики).
Построчно код не читал — где вывод сделан по структуре, а не по чтению реализации, это указано.

Дата слепка: 2026-10-21.

## 1. `trycompai/crm` ★12k · TypeScript · MIT

**Что это.** Открытая CRM, спроектированная не «с чатом сбоку», а так, что CRM — это место, где
агент ведёт заметки. Агент живёт в отдельном приложении (`apps/agent`), работает по своему
расписанию и по своей очереди задач, тратит бюджет на ресёрч и останавливается, когда бюджет кончился.

**Что реально интересно.**

1. **Отказ от confidence score.** В README прямо: ни один инструмент не принимает оценку
   уверенности, потому что модель, которую просят оценить свою уверенность, её завысит — и
   ошибётся в сторону «полезности». Вместо этого инструменты возвращают *наблюдения*
   (`crm.signature-block`, `github.account-identity`), а леджер назначает им цену. Сильное
   доказательство пишется в запись, слабое — становится предложением человеку.
2. **Состав агента как оглавление архитектуры.** В `apps/agent/agent/` лежат:
   `instructions.md`, `tools/` (24 файла: `identify_contact`, `research_company`, `record_fact`,
   `schedule_recheck`, `get_contact_work_history`…), `skills/` (4 файла: `evidence.md`,
   `identity-matching.md`, `data-boundaries.md`, `writing-a-brief.md`), `schedules/`, `subagents/`,
   `sandbox/`, `hooks/`, `channels/`. Это готовый скелет «как выглядит агент, который реально работает».
3. **Три правила, записанные там, где идёт работа** (а не в style guide):
   интеллект никогда не живёт в API (Nest сообщает факт, агент решает смысл);
   `packages/ui` — единственный источник UI; организаций нет — single tenant осознанно.
4. **Стек как референс:** Turborepo + Bun, Next.js App Router, NestJS + `nestjs-trpc`
   (типы от Prisma до ячейки таблицы), Better Auth, Prisma/Postgres, Vercel AI Gateway,
   состояние списков в URL через `nuqs`.

**Что забрать.** Паттерн «инструмент сообщает наблюдение → леджер оценивает → запись или
предложение». Это прямо переносимо на lovii-crm и на любые агенты, которые пишут данные о клиентах.

**Ограничение.** Заточен под Vercel-стек (AI Gateway, Sandbox, Blob). Локально придётся менять
провайдера моделей и песочницу. MIT — юридически чисто.

**Вердикт:** 🟢 не «CRM», а учебник по агент-first архитектуре. Читать `apps/agent` и `adrs/`.

## 2. `tw93/Mole` ★72k · Shell · GPL-3.0

**Что это.** CLI-инструмент для macOS: чистка, удаление приложений с остатками, оптимизация,
анализ диска в TUI, live-мониторинг. Команды: `mo clean`, `mo uninstall`, `mo analyze`, `mo status`,
`mo purge`, `mo installer`.

**Что реально интересно.**

1. **Безопасность как продуктовая фича, а не галочка.** Раздел Safety, `--dry-run` по умолчанию
   в сценариях с агентом, «удаление приложений и админ-шаги оставь человеку».
2. **Репозиторий подготовлен под агентов:** `llms.txt` (1.6 КБ — краткая инструкция для модели),
   `.agents/`, `.claude-plugin/`, `.cursor/`, `AGENTS.md`, `CLAUDE.md`. Плюс установка одной
   строкой через `npx skills add tw93/Mole`.
3. **Монетизация open-core:** бесплатный CLI в репозитории, платное нативное приложение отдельно.
   Честная модель, которую можно копировать.
4. Инженерная гигиена: `golangci.yml`, `shellcheckrc`, `gitleaks.toml`, `Makefile`, `.githooks`.

**Что забрать.** Схему «деструктивный инструмент, которому можно доверить агенту»:
dry-run → предпросмотр → подтверждение → лог. И `llms.txt` как обязательный файл.

**Ограничение.** GPL-3.0 — код нельзя втащить в закрытый продукт. Только идеи и UX.

**Вердикт:** 🟢 лучший в подборке пример «CLI + агентский скилл + нативное приложение».

## 3. `asafofer/perch` ★21 · Swift 6 · MIT

**Что это.** Приложение в «челке» Mac. Отвечает на один вопрос: «что я делал и что меня ждёт».
Показывает сессии Claude Code / Codex / OpenCode / pi, даёт разрешить или запретить команду
прямо из нотча и одной клавишей вернуться в нужную сессию — в терминал, точную вкладку
(Terminal, iTerm2, Ghostty, cmux), панель tmux/herdr или приложение.

**Что реально интересно.**

1. **Это редкая ниша: интерфейс не к агенту, а к *парку* агентов.** «Live status»: агенты сами
   сообщают момент завершения или запроса. Сортировка «сначала те, кому нужен я».
2. **Возврат в контекст как техническая задача.** Открыть «ту самую вкладку» — нетривиально;
   в репозитории это отдельный слой (Sources, scripts, Tests).
3. **Дисциплина тишины:** не забирает клавиатуру без запроса, молчит про сессию, в которой ты уже есть.
4. Репозиторий зрелый по структуре: `Package.swift`, `Sources/`, `Tests/`, `docs/`, `ui/`,
   `release-notes/`, `feedback/`, `scripts/` (включая `make-dev-cert.sh` — стабильная подпись,
   чтобы macOS не сбрасывал разрешения).

**Что забрать.** Идею «agent console в menu bar / нотче» для Dajet-линейки и схему
«статус + approve/deny + jump back» — её же можно сделать под свои скрипты.

**Ограничение.** Нишевое: macOS 15+, Apple Silicon, нужен нотч или верхняя панель. 21 звезда —
проект молодой, API агентов может меняться.

**Вердикт:** 🟢 самая свежая продуктовая идея в подборке; код на Swift 6 — читаемый образец.

## 4. `croffasia/itsaplan` ★1.7k · TypeScript · AGPL-3.0

**Что это.** Self-hosted трекер задач — открытая альтернатива Linear/Plane. Отличие: агент
получает роль, права и слот исполнителя и берёт задачи с той же доски, что и люди. Всё доступно
через REST, webhooks и MCP.

**Что реально интересно.**

1. **Агент как участник команды, а не как кнопка «сгенерировать».** Роли, права, назначение —
   это ровно те сущности, которых не хватает в самодельных «агентных» трекерах.
2. **Интеграционная поверхность с первого дня:** REST + webhooks + MCP + Docker/Coolify/Railway.
   То есть агент подключается любым способом.
3. **`DESIGN.md` в корне** — решения по продукту зафиксированы рядом с кодом (как `docs/design.md`
   у crm). Полезная привычка.
4. Полный issue-трекер сам по себе: проекты, доски, циклы, кастомные поля, дашборды — можно
   включить без единого агента.

**Что забрать.** Модель прав для агентов (что можно, что требует подтверждения) и MCP-сервер
как обязательный интерфейс, а не «потом добавим».

**Ограничение.** **AGPL-3.0** — для коммерческого white-label (LOVII) это стоп-сигнал,
только изучение и самостоятельная реализация. Проект сам предупреждает: до стабильного релиза
будут breaking changes.

**Вердикт:** 🟢 лучший референс «PM-система с агентами». Код — читать, лицензию — не втаскивать.

## 5. `thesysdev/openui` ★13k · TypeScript · MIT

**Что это.** Открытый стандарт generative UI: язык **OpenUI Lang**, который модель генерирует
потоком, и рантаймы, которые рисуют результат в React, Vue, Svelte, Angular.

**Что реально интересно.**

1. **Ключевая ставка — на язык, а не на библиотеку компонентов.** Компактный DSL вместо JSON:
   по бенчмаркам до **67% меньше токенов**. Это прямая экономия на каждом запросе.
2. **Стриминг как основа:** парсер ест токены по мере прихода и рисует постепенно, а не ждёт
   закрытия JSON.
3. **Промпт генерируется из библиотеки компонентов** — то есть список разрешённых компонентов
   и есть контракт для модели. Меньше галлюцинаций в разметке.
4. **Монорепо-архитектура — сама по себе урок:** `packages/lang-core` (парсер/компилятор),
   `react-lang`, `vue-lang`, `svelte-lang`, `angular-lang`, `react-ui`, `react-headless`,
   `assistant-ui`, `a2ui`, `server`, `openui-cli`, `devtools`, `observability`, `benchmarks/`.
   Ядро отдельно от рантаймов — поэтому и получилось четыре фреймворка.
5. Поддержка протокола **A2UI** и официальный Agent Skill для установки.

**Что забрать.** Идею «компактный DSL вместо JSON-схемы» для отчётов/дашбордов, которые
генерирует агент. Даже без OpenUI: свой мини-язык на 10 компонентов экономит токены и нервы.

**Ограничение.** Молодой стандарт; экосистема компонентов в основном React. Смотреть, насколько
жив Angular/Vue-путь, если понадобится.

**Вердикт:** 🟢 архитектурно самый интересный репозиторий подборки — после crm.

## 6. `danielmiessler/Fabric` ★44k · Go · MIT

**Что это.** CLI + библиотека «паттернов»: 266 прикладных промптов, каждый — отдельная папка
с `system.md`. Плюс REST API, хелперы (YouTube, PDF и т.п.), установка одним скриптом.

**Что реально интересно.**

1. **Паттерн как единица переиспользования.** Не «промпт-менеджер», а каталог: `extract_wisdom`,
   summarize, «написать эссе твоим голосом». Каждый — маленький, проверяемый, версионируемый.
2. **Философия декомпозиции:** AI — увеличитель человеческой креативности; большую задачу
   разбивают на куски и применяют AI к каждому отдельно.
3. **266 паттернов — это готовый корпус для своих RU-адаптаций** и источник структуры для
   собственной библиотеки скиллов.
4. Go-бинарь + REST-сервер: агент вызывает паттерны как локальный API.

**Что забрать.** Формат «папка = паттерн = system.md» и привычку держать библиотеку промптов
отдельно от кода продукта. Мои `agent-skills` — по сути та же идея, но без каталога.

**Ограничение.** Паттерны англоязычные и «под США» (стиль письма, контент-маркетинг). Нужна
адаптация, не копипаста.

**Вердикт:** 🟢 брать как каталог идей для промптов, не как зависимость.

## 7. `vercel-labs/agent-browser` ★44k · Rust · Apache-2.0

**Что это.** CLI для автоматизации браузера, сделанный *для агентов*, а не для тестов.
Нативный Rust-бинарь, ставится через npm/brew/cargo.

**Что реально интересно.**

1. **Семантические локаторы вместо CSS-селекторов** — «найди кнопку по смыслу», а не по
   `div > span:nth-child(3)`. Это ровно то, на чём ломаются агенты в реальном вебе.
2. **«Agent-friendly text»** — отдельная команда, которая отдаёт страницу в виде, пригодном
   для чтения моделью (а не 2 МБ DOM).
3. **Snapshot + state checking + wait** как первоклассные команды: агент сначала смотрит,
   потом действует, потом проверяет, что состояние изменилось.
4. **Репозиторий как продукт для агентов:** `evals/`, `benchmarks/`, `docs/`,
   `agent-browser.schema.json` (машинно-читаемое описание CLI), `.claude-plugin/`.
5. Apache-2.0 — можно использовать в коммерческих продуктах.

**Что забрать.** Заменить самодельные Playwright-скрипты на «snapshot → действие → проверка»
и отдавать агенту текстовое представление страницы, а не HTML. Схема `.schema.json` для CLI —
хороший приём: агент не гадает о флагах.

**Ограничение.** Молодой проект Vercel Labs; часть команд помечена экспериментальными (WebMCP).

**Вердикт:** 🟢 самый прикладной инструмент из восьмёрки — можно ставить сегодня.

## 8. `jaywcjlove/awesome-swift-macos-apps` ★1.8k · Swift · (awesome-list)

**Что это.** Курируемый каталог open-source macOS-приложений на Swift, разложенный по
категориям: Audio, Backup, Browser, Chat, Local LLM, AI, AI Usage/Status, AI Agent Monitoring,
Database, Development (Git, JSON, Web), Editors, Extensions и далее.

**Что реально интересно.**

1. **Это карта рынка, а не список ссылок.** По разделам видно, где уже тесно (браузеры, редакторы),
   а где пусто (AI Agent Monitoring — буквально один-два пункта; отсюда и Perch).
2. Для Dajet-линейки — доноры кода и UI-решения: Audio, Browser, Menu bar, Local LLM.
3. Раздел «AI Usage/Status» — готовый обзор того, как люди показывают расход токенов и лимиты.

**Что забрать.** Использовать как карту при выборе следующего Swift-продукта: искать
перенаселённые и пустые категории. Плюс список конкурентов для `dajet-player`/`dajet-editor`.

**Ограничение.** Awesome-list — это витрина, не гарантия качества; часть проектов заброшена.
Спонсорские блоки в шапке занимают больше экрана, чем сам список.

**Вердикт:** 🟡 не «идея», а рабочий инструмент выбора нишы.

## Сводка

| Репозиторий | Настоящая ценность | Что делать |
|---|---|---|
| trycompai/crm | агент-first архитектура, evidence-леджер | читать `apps/agent`, переносить паттерн |
| thesysdev/openui | язык генерации UI, экономия токенов | прототип своего мини-DSL |
| vercel-labs/agent-browser | автоматизация браузера для агентов | поставить и заменить Playwright-скрипты |
| danielmiessler/Fabric | 266 паттернов, формат библиотеки | адаптировать 10–15 под себя |
| croffasia/itsaplan | агент как участник команды, MCP | изучить права/роли; AGPL — не втаскивать |
| asafofer/perch | интерфейс к парку агентов | идея для Dajet-утилиты |
| tw93/Mole | безопасный деструктивный CLI + open-core | копировать UX-схему dry-run |
| jaywcjlove/awesome-swift-macos-apps | карта рынка Swift-приложений | использовать при выборе нишы |

**Общий вывод по восьмёрке.** Пять из восьми — про одно и то же: агент должен быть отдельным
процессом с инструментами, очередью, правами и доказательствами, а интерфейс человека должен
показывать статус и просить подтверждения. Это не мода, а уже сложившийся паттерн — и он
напрямую применим к LOVII и к Dajet-линейке.
