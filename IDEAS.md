# Идеи и полезные исходники

Два списка, ради которых всё затевалось:
1. **Идеи** — что забрать из звёзд в свои проекты. Не «когда-нибудь», а с привязкой к конкретному репозиторию.
2. **Исходники** — конкретные файлы/папки, которые стоит открыть руками (а не «весь репозиторий»).

Связанные файлы: [STARS.md](./STARS.md) (каталог), [STARS-REVIEW.md](./STARS-REVIEW.md) (разбор).

---

## Часть 1. Идеи

Формат: **идея → откуда → куда применить → объём**.

### A. Архитектура агентов

**A1. Леджер доказательств вместо confidence score.**
Откуда: `trycompai/crm` (`apps/agent/agent/skills/evidence.md`, `tools/record_fact.ts`).
Суть: инструмент возвращает не «я уверен на 0.8», а факт-наблюдение с источником; отдельный
слой решает, писать в запись или отдать человеку как предложение.
Куда: `lovii-crm`, любые агенты, которые заполняют карточки клиентов/заведений.
Объём: 1–2 недели на слой + переделка 3–5 инструментов.

**A2. Агент — отдельный сервис с очередью и бюджетом.**
Откуда: там же (`apps/agent` + `schedules/` + `subagents/`).
Суть: агент не вызывается из HTTP-запроса, а живёт в своём процессе, берёт работу из очереди,
имеет лимит «ресёрч-бюджета» и останавливается сам.
Куда: LOVII (проверка магазинов, обогащение каталога), AXIIOM (сбор лидов).
Объём: 2–3 недели, но снимает целый класс проблем «таймаут в проде».

**A3. Права агента как сущность продукта.**
Откуда: `croffasia/itsaplan`.
Суть: у агента есть роль, права и слот исполнителя; часть действий требует approve человеком.
Куда: внутренний трекер AXIIOM; `lovii-admin`.
Объём: 3–5 дней на модель прав, если есть RBAC.

**A4. Единый прокси над провайдерами моделей.**
Откуда: `lidge-jun/opencodex`, `razzant/claudexor`.
Суть: один клиент, много провайдеров, учёт квот и ротация. Не переписывать код при смене модели.
Куда: `opencode-setup`, `agent-skills`, любой свой агент.
Объём: 2–3 дня, если не изобретать протокол.

### B. Интерфейсы

**B1. Мини-DSL для генерации UI вместо JSON.**
Откуда: `thesysdev/openui` (OpenUI Lang, до −67% токенов).
Суть: 10–15 разрешённых компонентов + компактный синтаксис + стриминговый рендер. Промпт
генерируется из списка компонентов, поэтому модель не выдумывает разметку.
Куда: отчёты и дашборды, которые агент собирает по данным (LOVII-аналитика, отчёты для клиентов).
Объём: прототип — 3–4 дня; продакшн — месяц.

**B2. «Agent console» в menu bar / нотче.**
Откуда: `asafofer/perch`.
Суть: показать, что делают агенты, дать approve/deny не переключаясь, одной клавишей вернуться
в нужную сессию.
Куда: Dajet-линейка (первый кандидат — отдельная утилита `Dajet Agents`).
Объём: MVP 2 недели на SwiftUI + доступ к статусам через файлы/сокет.

**B3. Скилл, который отдаёт HTML-результат.**
Откуда: `larashero3-dotcom/lieflat-charts`.
Суть: не библиотека в проекте, а навык, который генерирует самостоятельный HTML-файл с графиком.
Куда: отчёты клиентам, презентации, `delivery-artifact`-подобные штуки.
Объём: 1–2 дня на один скилл.

### C. Инструменты и утилиты

**C1. Деструктивный CLI, которому можно доверять.**
Откуда: `tw93/Mole`.
Суть: `--dry-run` по умолчанию, предпросмотр, явное подтверждение, лог; отдельный
`llms.txt` + скилл, чтобы агент не удалил лишнего.
Куда: любые свои скрипты очистки/миграций; утилиты Dajet.
Объём: 2–3 дня, окупается сразу.

**C2. Автоматизация браузера: snapshot → действие → проверка.**
Откуда: `vercel-labs/agent-browser`.
Суть: семантические локаторы, текстовое представление страницы для модели,
проверка состояния после действия, машинная JSON-схема CLI.
Куда: замена самодельных Playwright-скриптов в агентах; сбор данных для каталога.
Объём: установка — час; переписать 3 сценария — 1–2 дня.

### D. Продукты

**D1. Агент-first CRM/PM для собственных нужд.**
Откуда: `trycompai/crm` + `croffasia/itsaplan`.
Суть: не «чат в CRM», а агент, который сам ведёт записи, и человек, который только подтверждает.
Куда: `lovii-crm` (уже есть заготовка).
Объём: большой, но можно начать с одного сценария — обогащение карточки заведения.

**D2. Self-hosted стартовая страница как внутренний портал.**
Откуда: `pawelmalak/flame`.
Суть: один вход ко всем сервисам AXIIOM/LOVII, свои закладки, поиск.
Куда: `axiiom.ru`-инфраструктура.
Объём: 1 день на поднять, дальше — вкусовое.

**D3. Моки платёжных провайдеров для тестов.**
Откуда: `rucorp/mock-services`.
Суть: имитация эквайринга и ОФД, чтобы тестировать сценарии оплаты без реальных ключей.
Куда: LOVII, любые финтех-демо (AXIIOM).
Объём: 2–3 дня.

### E. Медиа

**E1. Своя генерация музыки вместо API.**
Откуда: `koda-dernet/Side-Step` (ACE-Step 1.5).
Суть: CLI/TUI для обучения и запуска генерации треков локально.
Куда: `dajet`, `joer` — там уже AI-треки через Riffusion.
Объём: зависит от железа; начать с инференса, не с обучения.

**E2. Генерация презентаций по документу.**
Откуда: `presenton/presenton`.
Суть: документ → слайды, self-hosted, есть API.
Куда: КП и питч-деки AXIIOM (сейчас делаются руками).
Объём: 2 дня на пилот, дальше — шаблоны под бренд.

## Часть 3. Чему не подражать

- **AGPL в коммерческом продукте.** `itsaplan` — AGPL-3.0. Изучать можно, код в white-label LOVII — нет.
- **Складывание awesome-листов в звёзды.** Три подборки AI-агентов и две подборки скиллов дают
  почти ноль новой информации. Одну держать, остальные снять.
- **Скиллы без системы.** 380+ навыков в одном репозитории — это свалка; работает только
  каталог из 20–40 проверенных.
- **Копии форков в звёздах** (`1Crazymoney/agency-agents` — копия) и репозитории без описания
  (`kriptong/litca-ru`) — держать незачем.

## Часть 4. Как пополнять каталог

1. Раз в 2–4 недели: `gh api 'user/starred?per_page=100' --paginate > stars.json` и сравнить состав.
2. Новую звезду сразу записать в `STARS.md` в подходящую категорию: 1 строка описания + 1 строка «чем полезен».
3. Если репозиторий попал в работу — переносить в `IDEAS.md` с привязкой к своему проекту.
4. Раз в квартал: снять звёзды с мёртвых/бесполезных, обновить счётчик.
